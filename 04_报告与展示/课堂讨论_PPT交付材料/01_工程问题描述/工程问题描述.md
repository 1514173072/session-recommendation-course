# 工程问题描述

项目题目：基于图神经网络的电商会话推荐算法研究与实现。

## 1. 工程背景与应用场景

在电商平台中，用户会在一次访问过程中连续点击多个商品。平台可以根据已经发生的浏览行为，判断用户当前可能感兴趣的商品，并在推荐位中展示候选商品，辅助用户继续浏览。

一次访问中的连续交互可以组织成一个“会话”。会话推荐关注当前会话内的行为：用户依次点击了哪些商品，哪些商品被重复访问，以及这些点击之间存在怎样的联系。本项目使用匿名会话中的商品点击序列进行推荐，不依赖用户的长期画像或个人属性。

项目采用 Diginetica 交互数据。当前使用的数据文件包含会话编号、商品编号和时间戳三个字段；时间戳用于组织点击先后顺序，商品编号用于表示被点击的对象。数据中的商品以匿名 ID 表示，现有推荐输入没有商品名称或图片。

本项目对应的应用场景是：**用户已经浏览了一段商品序列，系统依据这段历史生成下一次点击的候选商品列表。**

## 2. 具体工程问题

本项目要解决的工程问题是：

> 给定当前会话中已经发生的商品点击序列，预测用户下一次可能点击的商品，输出按模型得分排序的 Top-10 推荐列表。

从输入到评价，任务包含以下环节：

| 环节 | 具体内容 |
|---|---|
| 输入 | 当前会话的历史商品点击序列，保留点击顺序与重复点击 |
| 处理 | 模型从历史序列及训练数据中学习商品关系，形成会话表示，并对候选商品打分 |
| 中间决策 | 按得分由高到低排列候选商品，选取前 10 个 |
| 输出 | 10 个商品 ID、对应排名及模型得分 |
| 离线核对 | 将推荐列表与预留的真实下一次点击商品进行比较，检查是否命中及命中排名 |

真实下一次点击是评价标签，不作为当前样本的模型输入。推荐列表允许包含历史中已经点击过的商品，因为用户可能再次点击同一商品。模型得分用于排序，不直接解释为购买概率。

当前系统支持对正式子集词表中的商品序列进行推理。它面向的是一次会话的下一点击预测；接入真实电商平台、库存与价格规则、在线服务和购买转化实验属于后续业务部署工作。

## 3. 问题难点

### 3.1 当前会话提供的信息有限

系统只能根据当前已经发生的点击推测下一步行为。较短的历史可能无法充分反映用户意图，而且相同的浏览记录也可能对应不同的后续选择，因此预测存在不确定性。

### 3.2 点击行为同时包含顺序、重复访问和商品关系

用户可能按照“商品 A → 商品 B → 商品 A → 商品 C”的顺序浏览。这里既存在前后转移，也存在对商品 A 的重复访问。模型需要组织这些行为信息，形成对当前会话的表示。

此外，其他训练会话中的商品连接关系可能为当前会话提供补充线索。如何使用当前会话关系与跨会话关系，是本项目比较不同图神经网络模型的切入点。

### 3.3 推荐效果与计算成本需要同时考虑

模型最终需要从候选商品集合中选出少量推荐结果。增加关系建模或注意力计算会改变模型的计算过程，其推荐效果和运行成本都需要通过实验检查。

因此，本项目既关注真实下一点击是否出现在推荐列表中，也关注其排名，以及模型对应的训练、验证和推理开销。理论复杂度与实际用时分别分析。

## 4. 研究目标与评价方向

本项目以 GCE-GNN 为主算法，以 SR-GNN 和 GC-SAN 为对照，在统一的数据与评价条件下研究会话推荐问题。

| 研究目标 | 实现或验证方式 | 希望回答的问题 |
|---|---|---|
| 实现完整推荐流程 | 完成数据准备、训练、测试、权重保存与加载，并提供交互推理界面 | 输入一段历史后，系统能否实际生成合法的 Top-10 推荐？ |
| 比较推荐质量 | 使用 Recall@10、MRR@10、NDCG@10 评价测试集结果 | 真实下一点击能否被推荐，以及排得是否靠前？ |
| 分析计算成本 | 结合代码推导时间复杂度，整理参数量及实测运行时间，并注明计时范围 | 不同模型的效果差异对应怎样的计算代价？ |
| 分析适用边界 | 检查不同会话条件下的表现，并展示真实失败案例 | 模型在哪些具体输入上失效，哪些解释还需要进一步验证？ |

当前正式实验使用 20,000 个会话的子集和一个训练随机种子。所得结果用于比较这套实验设置下三种模型的表现；跨会话信息的独立贡献需要进一步通过消融实验检验。离线点击预测指标用于评价推荐排序，实际购买转化或销售收益需要另行开展业务实验。

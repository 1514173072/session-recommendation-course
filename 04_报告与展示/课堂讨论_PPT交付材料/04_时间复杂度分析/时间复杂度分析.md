# 时间复杂度分析

本节依据当前 RecBole-GNN 源码，分析三种模型完成一次全候选商品预测所需的主要运算量，以 GCE-GNN 为重点。网络前向计算以已经构建好的局部会话图为输入；训练集全局图的初始化开销单独说明。

## 1. 分析对象与符号

| 符号 | 含义 | 当前设置或关系 |
| --- | --- | --- |
| L | 序列张量使用的长度上限 | 配置上限为 20；GCE-GNN 全局分支按该上限补齐计算 |
| U | 一条历史对应的局部图节点数 | 重复商品合并，因此 U ≤ L |
| E | 一条历史对应的局部图边数 | 由相邻点击、反向连接及自环构成，当前构图规则下 E = O(L) |
| d | 商品和会话表示维度 | 64 |
| K | 每个商品的全局邻居槽位数 | 12，邻居不足时也补齐为 12 个槽位 |
| M | 真实候选商品数 | 32,968；嵌入表另有填充索引 0，不影响渐近阶数 |
| N | 训练前缀样本数 | 97,273 |
| R | 实际训练轮数 | 最多 20 轮，由验证集选模和早停控制 |
| w | 全局构图使用的历史窗口 | 每个训练样本最近至多 4 次历史点击 |
| q_v | 全局商品 v 在截取邻居前的不同邻居数 | 用于分析邻居排序开销 |

以下采用普通稠密矩阵乘法的运算量口径。大 O 描述规模增长时的主要开销，不代表某次程序运行的具体秒数。单条样本公式也可作为固定配置下的长度上界；批量处理 B 条样本时，前向总运算量按相应批次张量规模增长。

## 2. GCE-GNN 分步时间复杂度

### 2.1 训练集全局图预构建

对应 `gcegnn.py` 中的 `construct_global_graph()`。

输入训练样本后，程序将每条样本的目标与最近至多 w 个历史位置建立双向关系并累计次数；随后将每个商品的全部邻居按计数排序，截取前 K 个，不足时补齐。

| 步骤 | 运算量 |
| --- | --- |
| 遍历训练样本并累计商品关联 | O(Nw)，采用字典插入与查询的期望常数时间口径 |
| 对每个商品的全部不同邻居排序 | O(Σ_v q_v log q_v) |
| 截取并生成固定长度邻接表 | O(MK) |

总开销为：

```text
T_global = O(Nw + Σ_v q_v log q_v + MK)
```

这里先排序全部邻居，再截取 12 个，因此排序开销取决于截取前的 q_v。该图在模型初始化时构建，随后训练和批量预测复用；不计入每条会话的重复前向开销。

### 2.2 单条会话的网络前向计算

| 阶段 | 输入 → 计算 → 输出 | 主要时间复杂度 |
| --- | --- | --- |
| 局部关系聚合 | 图节点嵌入与边类型 → 逐元素乘积、入边注意力与消息加权 → 局部节点表示 | O(Ed) |
| 全局邻居聚合 | L 个位置、每位置 K 个邻居、会话上下文 → 邻居注意力和线性变换 → 全局表示 | O(LKd² + Ld²) |
| 双分支相加 | 局部表示映射回序列，与全局表示逐位置相加 → 融合表示 | O(Ld) |
| 位置与上下文汇总 | 融合表示、位置嵌入和均值 → 线性变换、位置权重及加权求和 → 会话向量 | O(Ld²) |
| 全候选内积打分 | 会话向量与 M 个商品嵌入 → 全候选商品得分 | O(Md) |

全局邻居聚合中的 d² 项来自实际代码的矩阵乘法：每个邻居对应的“上下文与邻居逐元素乘积＋关联计数”向量，长度为 d+1，需要乘以形状为 (d+1, d) 的矩阵。因此，该分支的主项为 O(LKd²)。

当前配置只有一跳全局聚合。合并主要阶段后：

```text
T_GCE-GNN = O(Ed + LKd² + Ld² + Md)
```

利用 E = O(L)、K ≥ 1，可将主要项简写为：

```text
T_GCE-GNN = O(LKd² + Md)
```

模型输出的是全部商品的得分；预测导出程序随后屏蔽填充索引 0，再用 `torch.topk` 选出 10 个商品。Top-10 选择还需要读取候选得分，其具体实现开销取决于计算后端，不应把当前程序描述为先对全部商品进行完整排序。

### 2.3 从前向计算扩展到训练

训练时，每条样本还需要计算全类别交叉熵并反向传播。在固定网络结构、采用通常稠密运算的口径下，反向传播与对应前向计算同阶，常数开销不同。

R 轮训练的主要样本计算开销可写为：

```text
T_train = O(RN × (Ed + LKd² + Ld² + Md))
```

完整运行还包括全局图初始化、每轮验证、优化器更新、最终测试及数据准备。实际记录的“训练及验证耗时”包含每轮验证，不能直接视为上述纯训练样本公式的测量值。

## 3. 三模型对比与汇报重点

以下使用当前配置：SR-GNN 和 GC-SAN 均执行一步门控图传播；GC-SAN 使用一层、单头自注意力，其前馈层内部维度为 4d；GCE-GNN 使用一跳全局邻居。

| 模型 | 会话编码的主要开销 | 加上全候选打分后的复杂度 |
| --- | --- | --- |
| SR-GNN | 门控图传播 O(Ud² + Ed)，会话汇总 O(Ld²) | O(Ld² + Ed + Md) |
| GC-SAN | 图传播之外，自注意力增加 O(L²d)，投影与前馈变换为 O(Ld²) | O(Ld² + Ed + L²d + Md) |
| GCE-GNN | 局部关系聚合 O(Ed)，全局邻居聚合 O(LKd²)，位置汇总 O(Ld²) | O(Ed + LKd² + Ld² + Md) |

汇报时重点解释三个规模因素：

- **会话变长：**SR-GNN 的主要序列项随 L 增长；GC-SAN 还包含 L² 的注意力项；固定 K 时，GCE-GNN 的全局分支主要随 L 线性增长。
- **全局邻居增多：**在当前一跳设置下，GCE-GNN 的全局聚合主项随 K 线性增长。当前固定为 12 个邻居槽位。
- **候选商品增多：**三种模型均需对全部候选商品打分，具有共同的 O(Md) 项；因此编码机制之外，商品库规模同样影响计算成本。

本项目的序列上限只有 20，不能仅凭 GC-SAN 含有 L² 项就判断其实际运行一定更慢；矩阵乘法常数、邻居数、实际训练轮数、批量大小和硬件也会影响耗时。模型训练及验证耗时、参数量和推荐效果，结合“设计对比实验并分析结果”部分的真实结果表说明。

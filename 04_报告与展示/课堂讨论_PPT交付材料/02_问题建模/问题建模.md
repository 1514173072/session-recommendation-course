# 问题建模

## 1. 数据来源与数据说明

### 1.1 数据集出处

本项目使用 **Diginetica 电商会话数据集**，其公开发布背景为 **CIKM Cup 2016 Track 2: Personalized E-Commerce Search Challenge（个性化电商搜索挑战赛）**。数据来自电商搜索场景的用户会话日志，包含匿名化的用户、查询、商品及交互信息。本项目选用其中的商品点击交互，研究历史点击序列与下一次点击之间的关系。
### 1.2 数据字段与含义

完整交互文件采用制表符分隔，包含以下三个字段。每行代表一次商品点击：

| 文件中的字段 | 含义 | 在本项目中的作用 |
|---|---|---|
| `session_id:token` | 会话编号 | 将属于同一会话的点击组织在一起；会话编号不等同于真实用户身份 |
| `item_id:token` | 匿名商品编号 | 标识被点击的商品，随后映射为内部嵌入索引 |
| `timestamp:float` | 点击时间戳 | 在同一会话内组织点击先后顺序 |

字段名称后的 `token`、`float` 为 RecBole 的类型标记。商品 ID 是类别标识，其数值大小不表示商品之间的距离。当前使用的交互文件包含商品编码，不包含可直接展示的商品名称或图片。

### 1.3 完整交互文件与正式实验子集

| 数据范围 | 会话数 | 交互中出现的不同商品数 | 点击记录数 |
|---|---:|---:|---:|
| 下载的完整交互文件 | 204,789 | 43,136 | 993,483 |
| 项目筛选并抽取的正式子集 | 20,000 | 32,968 | 157,273 |

正式实验子集由完整交互文件经过商品频次过滤、会话长度筛选和固定种子抽样得到。下文的建模、样本划分与实验均以该 20,000 会话子集为对象；具体筛选规则见第 3 节。

## 2. 输入、输出与符号定义

本项目将电商会话推荐建模为一个有监督的下一点击预测与排序问题：给定已经发生的商品点击序列，学习当前会话的表示，对候选商品打分，并输出得分最高的 10 个商品。

### 2.1 输入

设一条完整会话按时间排序后为：

```text
S = (v_1, v_2, …, v_L)
```

其中，`v_t` 表示第 `t` 次点击的商品，`L` 表示完整会话的点击次数。预测第 `t` 次点击时，模型只能使用此前的历史：

```text
X_t = (v_1, v_2, …, v_(t−1))
y_t = v_t
```

`X_t` 为输入，`y_t` 为真实下一点击标签。商品允许重复出现，因此点击次数与不同商品的数量可以不同。

数据中的会话编号用于将点击组织为一条会话，时间戳用于确定点击顺序。当前模型以商品序列及其图结构作为主要输入，不将商品 ID 的数值大小解释为商品之间的距离。

### 2.2 输出

设真实候选商品集合为 `I`，商品数量为 `M`。模型为每个候选商品计算得分，输出有序推荐列表：

```text
R_10(X_t) = Top10{ z_j(X_t) : j ∈ I }
```

其中，`z_j(X_t)` 是商品 `j` 在当前历史下的模型得分。Top-10 按得分从高到低排列，每个商品只出现一次。历史中已经点击过的商品仍可以进入推荐列表。

### 2.3 主要符号

| 符号 | 含义 | 当前项目设置 |
|---|---|---|
| `S` | 按时间排列的完整会话 | 来自 Diginetica 正式子集 |
| `L` | 完整会话点击次数 | 5–20 |
| `X_t` | 预测第 `t` 次点击时的历史 | 包含前 `t−1` 次点击 |
| `y_t` | 当前样本的真实下一点击 | 单个商品 |
| `I`、`M` | 真实候选商品集合及其大小 | 32,968 个商品 |
| `d` | 商品与会话表示的维度 | 64 |
| `θ` | 模型需要学习的参数 | 商品嵌入及各模型网络参数 |
| `K` | 推荐列表长度 | 10 |

## 3. 数据处理与监督样本构造

### 3.1 正式数据范围

当前使用的数据为完整 Diginetica 交互数据经过筛选和抽样得到的正式子集。处理步骤为：

1. 在完整交互数据上统计商品频次，保留出现至少 5 次的商品。
2. 保留过滤后点击次数为 5–20 的会话。
3. 排除前期用于小规模试跑的 2,000 个会话。
4. 使用抽样种子 2026，选取 20,000 个会话，并保留其过滤后全部点击。
5. 在各会话内部按时间组织点击，构造历史与下一点击配对的监督样本。

| 数据项 | 数量 |
|---|---:|
| 正式会话 | 20,000 |
| 不同商品 | 32,968 |
| 点击记录 | 157,273 |
| 训练样本 | 97,273 |
| 验证样本 | 20,000 |
| 测试样本 | 20,000 |

点击记录数、会话数和监督样本数是不同的计数单位。一条完整会话可以产生多条“历史序列 → 下一点击”训练样本。

### 3.2 会话内留尾划分

对长度为 `L` 的会话，先生成 `L−1` 条前缀预测样本，再按目标点击的位置划分：

| 用途 | 输入历史 | 预测目标 | 每个会话的样本数 |
|---|---|---|---:|
| 训练 | `(v_1, …, v_(t−1))`，`t = 2, …, L−2` | `v_t` | `L−3` |
| 验证 | `(v_1, …, v_(L−2))` | `v_(L−1)` | 1 |
| 测试 | `(v_1, …, v_(L−1))` | `v_L` | 1 |

因此，训练样本总数为：

```text
Σ[s = 1, …, 20,000] (L_s − 3)
= 157,273 − 3 × 20,000
= 97,273
```

这是同一会话内部按预测位置划分的留尾协议：同一会话会出现在训练、验证和测试样本中，各样本的目标位置不同，历史前缀可以重叠。测试时，倒数第二次点击已经发生，可以进入测试历史；最后一次点击仍作为预留标签。

模型参数使用训练样本学习，最优权重根据验证集 MRR@10 选择，测试样本用于最终评价。该协议评价的是当前数据与词表条件下的下一点击能力，未采用全平台统一时间截断来模拟未来上线；商品频次筛选与词表确定在划分前完成。

### 3.3 编码与长度处理

原始商品 ID 被映射为连续的内部整数索引，用于查找可学习的商品向量。内部索引 0 用于填充，真实商品对应其余 32,968 个索引。

配置中的最大历史长度为 20。当前完整会话最长为 20 次点击，因此测试历史最长为 19 次；训练与验证历史更短。批处理中的填充位置由掩码区分，推荐输出排除填充索引。

## 4. 会话的图结构表示

### 4.1 当前会话图

将输入历史 `X_t` 表示为会话图：

```text
G_t = (V_t, E_t)
```

其中，`V_t` 是历史中出现的不同商品集合；基础有向边集合为：

```text
E_t = { (v_i, v_(i+1)) : i = 1, …, t−2 }
```

相邻点击构成有向连接，同一商品的重复访问映射到同一节点。图结构之外还保留每个点击位置到节点的映射，使节点表示能够还原为按原顺序排列的序列表示。

SR-GNN 与 GC-SAN 的当前实现对相同有向边去重。GCE-GNN 进一步使用正反方向、双向关系与自环等边类型，其具体构图与传播步骤在“算法设计思想与伪代码描述”部分展开。

### 4.2 跨会话商品关系

GCE-GNN 还使用从训练样本构建的全局商品图，节点表示商品，连接权重反映代码规定窗口内的商品关联计数。该图为当前会话中的商品补充跨会话邻居信息。

全局图的关联计数来自训练样本；验证与测试样本不加入这些计数。具体窗口、邻居截取和聚合方式属于算法实现细节，后续单独说明。

因此，建模的信息流可以概括为：

```text
按时间排列的历史商品序列
    ↓ 商品编码、会话构图、位置到节点映射
当前会话图；GCE-GNN 另使用训练样本构建的全局商品图
    ↓ 模型编码
会话向量
    ↓ 与候选商品向量计算得分
Top-10 推荐列表
```

## 5. 候选打分与训练目标

### 5.1 会话表示与商品得分

设模型编码器为 `f_θ`，输出 `d` 维会话向量：

```text
h_t = f_θ(X_t)
```

这里用 `X_t` 简写编码器输入；实际计算包含前述图结构，GCE-GNN 还使用训练全局图。设商品 `j` 的嵌入为 `e_j ∈ ℝ^d`，三种模型均使用内积计算候选得分：

```text
z_j(X_t) = h_tᵀ e_j
```

推理时对全部真实候选商品打分并取前 10 个。得分反映模型给出的相对排序，不直接表示购买概率。

### 5.2 交叉熵目标

正式配置采用交叉熵损失，使用真实下一点击作为类别标签。对于一条训练样本，目标是提高真实目标相对于其他类别的得分。

按照当前源码，训练 logits 包含整个嵌入表，包括填充索引 0。单样本损失写为：

```text
ℓ(X_t, y_t; θ)
= −z_(y_t)(X_t) + log( Σ[j = 0, …, M] exp(z_j(X_t)) )
```

真实标签始终对应真实商品。预测输出与评价时，填充索引 0 被屏蔽。当前配置不使用负采样，而是进行全类别交叉熵训练。

总体学习目标为：

```text
θ* = argmin_θ {
       (1 / |D_train|) × Σ[(X,y) ∈ D_train] ℓ(X,y;θ)
       + R(θ)
     }
```

其中，`R(θ)` 表示具体模型实现中使用的附加正则项。当前 GC-SAN 对商品嵌入加入正则项，系数为 `5 × 10⁻⁵`；SR-GNN 与 GCE-GNN 的该损失函数直接返回交叉熵。具体优化配置在对比实验部分列出。

## 6. 评价指标与判断标准

每个验证或测试样本只有一个真实下一点击商品。设测试样本数为 `N`，第 `n` 个样本的真实商品排名为 `r_n`，定义命中标记：

```text
H_n = 1，若真实商品的排名 r_n ≤ 10
H_n = 0，若真实商品未进入前 10 位
```

三项主要指标为：

```text
Recall@10 = (1/N) × Σ[n = 1, …, N] H_n
```

```text
MRR@10 = (1/N) × Σ[n 满足 r_n ≤ 10] (1/r_n)
```

```text
NDCG@10 = (1/N) × Σ[n 满足 r_n ≤ 10] [1/log₂(r_n+1)]
```

| 指标 | 衡量内容 | 解释 |
|---|---|---|
| Recall@10 | Top-10 的目标命中比例 | 越高，说明更多样本的真实下一点击进入推荐列表 |
| MRR@10 | 命中排名倒数的平均值 | 对靠前排名给予更高分数，未命中记 0 |
| NDCG@10 | 经对数折扣后的排名质量 | 奖励靠前的命中；单个真实目标时理想折扣增益为 1 |

在当前单目标设置下，Hit@10 与 Recall@10 相同，Precision@10 等于 Recall@10 除以 10。它们可以作为补充输出，不作为独立的效果证据重复解释。

后续在相同数据、划分与候选集合上比较三种模型，并结合复杂度、参数量和注明计时范围的运行时间，分析推荐效果与计算成本之间的关系。

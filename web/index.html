01
THE SETUP

实验全景

数据从完整 Diginetica 出发，先做全局 item 5-core，再抽 20,000 个真实会话。三个模型共享同一份训练、验证、测试划分。

!

为什么是 20k，不是全量？ 全量 20 万会话在 CPU 上训练三模型成本过高；20k 是固定种子的随机子集，足以比较模型，也保证一次闭环能在数十分钟内完成。

?

评价口径 每个测试会话只留一个真实“下一次点击”，模型对全部候选商品打分，取 Top-10。Recall@10 等于命中会话占比。

三项指标

Recall / MRR / NDCG @10

MRR 与 NDCG 同时反映命中商品的排名位置，不只看“有没有进前十”。

04
ONE SESSION, THREE MODELS

会话回放

选一个真实测试会话，切换模型，看它把哪些商品排进前十，以及真实下一商品落在第几位。

Top-10 推荐

条形长度为模型得分，不是购买概率；绿色为真实下一商品，红色表示它没有进入 Top-10。商品 ID 来自 Diginetica 匿名编码。

05
WHAT THE MODEL SEES

模型看见了什么

同一段浏览序列变成有向图：节点是商品，边是连续点击。GCE-GNN 还会从训练集里取当前商品的全局邻居。

A

局部图 节点大小表示该商品在本次会话中出现的次数；重复点击会形成回访边。

B

全局邻居 来自训练集的商品共现关系，只展示当前会话最后一个商品的邻居，不表示注意力权重。

C

读图边界 图用于解释信息流，不用来证明“模型一定因为这条边而推荐”。

06
FAILURE & BOUNDARY

失败与边界

整体指标更高的模型，也会在具体会话上失败。下面保留真实失败案例，并写清这次实验不能证明什么。

DATA

匿名商品 ID

Diginetica 只提供编码后的商品标识，无法还原名称、图片或品类。页面展示的是真实行为与真实排名，不是商品内容。

EVIDENCE

单种子、单次实验

本轮固定 seed=42，只报告一次运行结果。没有多种子均值与标准差，不能据此宣称统计显著。

ATTRIBUTION

没有做消融

三模型对比不能单独证明“全局关系带来提升”。要回答这个问题，需要去掉全局分支的 GCE-GNN 对照。

SOURCE

SCOPE

20,000 个测试会话、20 轮、单种子；训练与验证时间包含保存，不含数据准备、环境安装与 GCE 全局图构建。

# 电商会话推荐：完整实现方案

这个方向可以正式作为你的课程项目。我建议题目定为：

《基于图神经网络的电商会话推荐系统设计与算法性能分析》

使用 [RecBole-GNN](https://github.com/RUCAIBox/RecBole-GNN?utm_source=chatgpt.com) 作为算法后端，选择 SR-GNN、GC-SAN 和 GCE-GNN 三种模型，使用真实电商数据 Diginetica，最终做成一个可以选择模型、输入浏览序列、生成商品推荐、查看算法实验结果的系统。

先回答你最关心的两个问题。

1\. 官方项目是否完整？

作为算法研究框架，比较完整；作为一个可以直接给用户操作的电商推荐应用，还不完整。

2\. 需要自己补多少内容？

无需重新编写三个神经网络，主要需要补齐模型推理接口、实验结果可视化、统一交互页面，以及运行环境的兼容性处理。

## 二、从用户行为到最终推荐的完整流程

阶段1 · 数据输入

真实电商浏览记录：session_id、item_id、timestamp

阶段2 · 数据处理

按会话和时间排序 → 生成历史序列与下一商品标签

阶段3 · 图结构构建

商品作为节点，连续点击作为有向边

SR-GNN

会话图传播

GC-SAN

图表示＋注意力

GCE-GNN

局部图＋全局图

阶段4 · 模型训练

计算推荐分数 → 交叉熵损失 → 反向传播 → 保存最优模型

阶段5 · 推理与可视化

输入新会话 → 推荐 Top-10 商品 → 展示评价指标和图表

这里有两个需要区别的过程：训练阶段用历史交互与实际下一商品学习模型参数；演示阶段加载保存的模型，根据当前会话生成推荐，无需每输入一次浏览记录就重新训练模型。

## 三、实际开发分为五个阶段

### 阶段1：搭建环境，准备真实数据

推荐使用 Python 3.9 的独立 Conda 环境。由于 RecBole-GNN 最后一次代码更新是在2023年，最好在 Windows 的 WSL2/Linux 环境中安装一套相互兼容的 PyTorch、PyTorch Geometric 和 `torch_sparse`，降低依赖冲突风险。

```
git clone https://github.com/RUCAIBox/RecBole-GNN.git
cd RecBole-GNN
```

核心依赖需要包含 `recbole==1.1.1`。具体 PyTorch 与 PyG 版本应配套安装，而不是全部直接使用最新版本。

数据集选择：

`diginetica-not-merged`

RecBole 已登记了它的处理版下载地址，理论上可以自动下载，若自动下载失败，再手动放入 `dataset/diginetica-not-merged/`。

[image](https://www.google.com/s2/favicons?domain=https://recbole.io\&sz=32)

RecBole 1.2.1 documentation



建议创建 `configs/diginetica.yaml`：

```

USER_ID_FIELD: session_id
ITEM_ID_FIELD: item_id
TIME_FIELD: timestamp

load_col:
  inter: [session_id, item_id, timestamp]

ITEM_LIST_LENGTH_FIELD: item_length
LIST_SUFFIX: _list
MAX_ITEM_LIST_LENGTH: 20

user_inter_num_interval: "[5,inf)"

epochs: 50
train_batch_size: 1024
eval_batch_size: 2000
stopping_step: 10

train_neg_sample_args: ~

metrics: ['Recall', 'MRR', 'NDCG', 'Hit', 'Precision']
topk: 10
valid_metric: MRR@10

eval_args:
  split: {'LS': 'valid_and_test'}
  order: TO
  mode: full

```

这是参考官方设置缩小训练规模的首次测试配置，目的是先确认整个流程能跑通。正式复现官方排行榜时，需恢复对应的500轮训练上限、模型最优参数及完整实验条件。

### 阶段2：训练三个模型

```

# 基础会话图推荐
python run_recbole_gnn.py -m SRGNN -d diginetica-not-merged --config_files configs/diginetica.yaml

# 图神经网络 + 自注意力
python run_recbole_gnn.py -m GCSAN -d diginetica-not-merged --config_files configs/diginetica.yaml

# 局部与全局图增强
python run_recbole_gnn.py -m GCEGNN -d diginetica-not-merged --config_files configs/diginetica.yaml

```

运行成功后，每个模型应产生最优模型权重、训练日志、验证指标和测试指标。

需要注意，三者虽然可以使用共同的数据划分和评价协议，但合理的超参数并不一定完全相同。特别是 GCE-GNN 包含额外的全局图构建过程，不能把它当成仅仅替换一下模型名称就完全等价。

### 阶段3：新增推荐推理接口

这是仓库现成训练功能与完整应用之间最重要的差距。

在官方代码中，三个模型都有 `full_sort_predict()`，能够给候选商品计算推荐得分；但输入必须是模型要求的张量和图结构，而不是普通商品 ID 列表。

因此需要新增 `predictor.py`，完成：

输入示例（仅展示格式）

`[21553, 20071, 8762]`

后端执行

原始商品 ID → 内部 ID → 构造会话图 → 加载模型 → 计算得分 → Top-10 排序

输出格式

```

{
  "model": "SRGNN",
  "input_items": [21553, 20071, 8762],
  "recommendations": [
    {
      "item_id": "<actual_item_id>",
      "score": "<actual_model_score>",
      "rank": 1
    }
  ]
}
  
```

以上是接口设计示例，商品 ID 并非实际预测验证案例，得分需由训练模型产生。

三个模型需要分别适配会话图输入。尤其是 GCE-GNN 还使用了全局商品关联信息，因此不能完全共用 SR-GNN 的图构建方法。

建议先实现“选择测试集中的已有会话并预测”，确认与离线评价一致后，再支持任意有效商品 ID 序列。这样可以减少推理阶段的错误。

## 七、还有哪些困难？

| 风险    | 具体问题                                      | 建议处理方式                  |
| ----- | ----------------------------------------- | ----------------------- |
| 环境兼容  | PyTorch、PyG、`torch_sparse` 与旧版 RecBole 冲突 | 优先隔离 Linux/WSL2 环境，固定依赖 |
| 数据规模  | Diginetica 比 MovieLens-100K 大             | 首先缩小训练轮数完成连通性测试         |
| 自定义推理 | 官方偏重训练与离线评价                               | 先基于测试会话推理，再做任意序列输入      |
| 商品展示  | 商品数据匿名化                                   | 优先展示真实 ID、排名和分数，不伪造商品信息 |
| 可视化   | 官方没有统一 Streamlit 应用                       | 采用轻量前端补齐                |
| 模型比较  | 不同网络训练成本不同                                | 统一数据和评价协议，并记录性能与成本      |

我对这个项目的最终建议是：先把 SR-GNN 与 GCE-GNN 做成完整的双模型电商推荐演示，GC-SAN 作为第三个对照模型加入。

这样你的研究主线非常明确：从局部会话图建模，到全局上下文增强，研究推荐质量改善与计算成本之间的关系。

课程汇报可以分为实际应用演示、算法原理和实验评价三部分，最终会比单纯跑出几张预测曲线更完整。

项目的主体算法确实已经存在，新增工程量集中在接口与可视化；但截至目前，我完成的是源码及数据接口核查，不是实机运行验收。只有环境、三模型训练、推理与页面逐项测试通过后，才能说它完全运行成功。
